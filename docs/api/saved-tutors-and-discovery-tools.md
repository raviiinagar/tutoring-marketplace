# Saved Tutors, sharing and discovery tools

`GET /v1/me/saved-tutors` requires a current active verified account session and returns `{items,limit:50}`. Each item contains only `profile_id`, `saved_at` and the currently eligible public profile, or null if unavailable. Current identity/publication, safety restrictions, expired approvals, disabled accounts and either-direction blocks are checked. Saving a free public introduction does not require Pro or a Learner Access Pass.

`POST /v1/me/saved-tutors/:profileId` with `{}` saves an eligible public profile. `DELETE` removes only the signed-in account's entry, including an unavailable target. Normal JSON/Origin/session controls apply. Duplicate saves/removes are idempotent; serialised account writes enforce at most 50 saves, including unavailable placeholders. Full lists reject new additions with `SAVED_TUTOR_LIMIT`/409; an existing save remains idempotent. Saves notify nobody and confer no request, contact or booking entitlement. Reads use fresh public projections; the table stores no biography, contact, evidence or identity snapshots.

Account exports include owned profile references/timestamps. Full erasure removes saves owned by an erased account and saves referencing an erased Tutor, coordinated against concurrent additions. Older restore schemas remain guarded. The UI uses account-specific memory query keys and no persisted shortlist/contact snapshots in browser storage. `/saved-tutors` supports signed-out, retry, empty and unavailable states. Profile sharing is an explicit user action through native share, clipboard or a selectable canonical same-origin public profile URL with no query/fragments; cancelled share sheets do not auto-copy.

Discovery GET and observed-search POST accept `trial_kind=FREE` and optional `sort=PRICE_ASC|PRICE_DESC`. FREE means the exact offer contains a Tutor-offered free introductory class with its stated duration; it does not discount the platform pass. Sorting requires one `rate_unit=HOUR|LESSON` to avoid mixing different tuition units. The UI explicitly selects hourly rates when enabling price sort without a unit and clears sort if the unit is cleared. Existing min/max filters and exact-offer dimensions remain authoritative.

Default pagination remains UUID ascending. Price order uses integer rate plus UUID ascending as a stable tie-breaker. Its bounded versioned cursor contains only public rate/ID/order/unit; malformed or mismatched order/unit cursors return INVALID_FILTER/400. The cursor is a position, not authority, and all visibility/filter rules are reapplied. It remains usable if the preceding offer disappears. No ranking, review or price is fabricated. Introductory profile cards are suppressed when offer-only sorting/trial filters apply, so indicative profile rates are not represented as exact matched offer prices. Legacy availability alerts strip display-only sort and do not accept trial filters.
