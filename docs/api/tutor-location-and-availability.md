# Tutor location and usual availability

ADR-0013 expands the online launch to city/area-based in-person discovery. `GET /v1/me/tutor/presence` returns the signed-in account's saved preferences; `POST` requires the Tutor role and an existing introduction. Normal session, Origin and account-status checks apply.

Save a strict body containing `expected_revision` (0 initially), `location` (null or city, optional area/state and country, default India), distinct `teaching_modes` (`ONLINE`, `IN_PERSON`), `accepting_students`, `weekly_slots` and `timezone: Asia/Kolkata`. Each slot has `day` MON–SUN, `start_minute` 0–1439 and later `end_minute` 1–1440. At most 21 non-overlapping slots; split overnight windows into separate days. In-person mode requires a city. Named place fields are limited to 80 characters and reject obvious contact/coordinate-only inputs; the UI asks for coarse locations, not exact addresses. These checks are not a complete address or personal-information classifier.

Successful writes return `presence` and `offers_need_review`. Stale writes return `PRESENCE_CHANGED`/409. Settings edits preserve identity approval. A material in-person location change, or removal of an offer's mode, moves affected REVIEW/PUBLISHED/PAUSED offers to CHANGES_REQUESTED with a new revision. Resubmit for review. Temporarily declining new students hides new supply and new enquiries without changing the offer revision or invalidating covered pending enquiries and safe Connections. Independent identity, safety, entitlement and expiry rules continue to apply.

Public profiles, discovery offers and offer detail include a safe `presence` projection. Existing profiles without saved preferences remain compatible with online offers and report `accepting_students: null`, displayed as availability not shared. Profile visibility is independent of Pro and new-enquiry acceptance; consented public email still requires an eligible offer.

`GET /v1/tutor-profiles/locations?q=...` suggests up to ten coarse locations from currently eligible, accepting, in-person public profiles. Static Indian city suggestions in the UI are search shortcuts and do not imply available Tutors. No GPS, geocoding provider or kilometre-distance claim is used.

Discovery and public profile queries accept `location` (case-insensitive city/area/region substring), optional exact `country`, `teaching_mode`, `day`, `at_time` (0–1439, requires day), and `accepting_only=true`. Time matches start-inclusive/end-exclusive declared hours in IST. Discovery additionally matches the exact offer mode; existing offer taxonomy/price filters remain authoritative. Profile search supports Subject plus presence filters; the UI directs exact-offer-only filters to offer results. Weekly hours are usual preferences, not live calendar availability or a booking.

Teaching offers and Contact Requests accept one `ONLINE` or `IN_PERSON` mode. In-person offers require saved matching preferences. Requests snapshot the coarse `class_location`; full erasure removes saved presence and strips this retained snapshot field. Account exports include owned preferences. Legacy availability alerts continue to cover online offers only; the UI suppresses signup for unsupported location/time filters.
